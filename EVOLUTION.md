# Open-quality evolution goal

This is a lightweight cross-session state record, not runtime authority. The
Kernel, selected Profile, and user/project contract still govern execution.

## Goal and non-goals

Upgrade this repository from “finish explicit work reliably” to a measured
capability that also improves direction choice, representative examples, real
acceptance, and delivery consistency on open-ended work.

Success means higher blind quality and lower variance per WCU and per user
correction, while bounded tasks keep their direct edit → focused check → diff
path. It does **not** mean a universal workflow, more agents, more documents,
automatic product/research direction authority, or promotion by showcase.

## Frozen decisions

- A bounded task with a direct Oracle uses the fast path; quality adjectives do
  not trigger Option Search by themselves.
- Option Search is a single optional activity for an unresolved material
  product/research/architecture fork. It may compare and kill candidates but
  cannot weaken the contract or approve a new user commitment.
- An approved proposal goes to Research Execution. A material change to its
  claim, method, benchmark, data, analysis, or budget is `re_contract`, not a
  convenient new idea.
- Product-scale expansion starts only after a representative vertical slice has
  passed claim-matched product, architecture, and—when claimed—visual Oracles.
  The passed slice is the golden implementation; an invalid slice is repaired,
  killed, or re-contracted before scale.
- Durable state is conditional on real recovery needs. An outer loop is eligible
  only when contract, Oracle, state, and decomposition are all ready.
- Development v4, Option Search v1, Adapter v5, and any future Skill remain
  candidates until controlled evidence beats strong native Codex and the prior
  SOP. No net lift means delete or disable the mechanism.

## Capability and failure baseline

| Work is dominated by | Existing strongest path | Baseline fact / gap | Candidate intervention |
|---|---|---|---|
| Judgment | Kernel contract plus native model reasoning | Open product and research-idea work had no dedicated entry for comparing materially different directions; the first plausible direction could become the implementation by accident | Optional `option-search`; it ends at a reversible choice, kill, unresolved result, or HUMAN boundary, then hands execution back to an existing Profile |
| Evidence | Build Oracle and Research Execution Grill | Approved-method fidelity is comparatively strong; complete-product, visual, and real browser evidence was uneven and useful PR #24 semantics never reached `main` | Development v4 delivery grade, representative/golden slice, real integration/render evidence, and one conditional independent visual observation |
| Execution | Kernel plus one selected Domain Profile | Clear engineering work already had a viable direct path; a universal discovery/review loop would be a regression | Explicit bounded fast path and frozen-direction execution; no Option Search, durable record, browser gate, or review ceremony without a concrete trigger |
| Coordination | Codex Adapter roles, goals, provenance, and audit | Role routing exists; recovery facts and autonomous-loop eligibility were not stated as one small decision boundary | Conditional continuity record plus contract/oracle/state/decomposition readiness and repeated-no-information/complexity stop rules |

The baseline already has strong native reasoning, repository reading, planning,
delegation, implementation, and ordinary review. This change does not recreate
those capabilities. It narrows when to spend them and what evidence must change
the next decision.

| Observed failure | Trigger signal | Smallest intervention | Oracle and removal condition |
|---|---|---|---|
| First reasonable direction is implemented at scale | An unresolved fork changes user value, research claim, or a core invariant and wrong choice dominates cost | Compare material operations and run the cheapest decisive probe | Blind open-task quality/late redesign; remove if no net lift over strong native Codex |
| Runnable UI still looks generic or breaks the journey | Product-grade UI is claimed but information hierarchy/visual identity or real states are unproven | Freeze a domain direction, validate one golden slice, walk it in a real browser, take one independent critique pass | Same-state screenshots plus interaction/console/network trace and blind review; remove any reminder/Skill that loses to raw/minimal control |
| Research idea is terminology-rich but operation-poor | No explicit signal, closest operational neighbor, falsifier, or real benchmark probe | Candidate packet, collision search, and kill-first decisive experiment | Blind novelty/clarity/impact and early-kill quality; keep `NOT_ESTABLISHED` when evidence is absent |
| Approved research drifts toward an easier claim | Method, benchmark, data, metric, baseline, or budget would materially change | Existing Research Execution fidelity mapping and `re_contract` | Independent method Oracle; any silent change is a hard failure, not a new option |
| Outer loop accumulates patches without information | Same failure repeats or local fixes add complexity without improving the Oracle | Stop and revisit the local design/assumption | Complexity and direct Oracle trend; stop rather than add another fallback |
| A small edit triggers agents and artifacts | Scope and direct Oracle are already bounded | Fast path only | 100% Oracle, zero heavy trigger/artifact/agent, WCU ≤1.10× and elapsed ≤1.25× the stronger control; violation blocks promotion |

## Current mechanism decisions

|---|---|---|
| `KEEP` | Existing Kernel authority, Research Execution fidelity, proportional Oracle, and simple-task execution path | They address observed failure paths and already have repository/runtime evidence; this candidate does not create a parallel authority |
| `EXPERIMENTAL` | Option Search v1, Development v4 product/visual loop, Adapter v5 readiness/role guidance | Semantics and regression tests exist, but controlled outcome lift has not been measured |

| `REVISE` | Remaining Skill/Hook/strict-protocol candidates | Keep disabled until a frozen task shows net lift, then retain only the causal minimum |
