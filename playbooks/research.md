# Playbook: 已批准 proposal 的实现与实验

适用于把已经批准的研究 proposal 忠实地实现出来并跑实验。idea 还没批准时不用这一份。这里只列研究特有的证据要求；实现和实验怎么组织由 agent 决定。通用规则见 [KERNEL](../KERNEL.md)。

## 契约

动手前冻结以下各项：

- 核心 claim 与 primary estimand；
- 方法语义；
- baseline；
- 数据与 split；
- 分析方法；
- 成功条件与 kill 条件；
- 预算。

任何一项要实质改变，都要回到人。不能用一个更容易的 claim 替代原任务。

## 方法忠实

第一次经验性 run 之前，把 proposal 的关键语义（公式、loss、mask、更新规则等）映射到代码位置，并给每条配一个独立检查：小规模确定性 fixture、naive 参考实现、独立推导或性质测试都可以。loss 下降和端到端分数不能证明方法实现正确。

## 实验设计

- baseline 与本方法使用相同的数据和信息，调参预算可比。
- 调参集和最终证据集分开。
- 声称机制时，要有能区分替代解释的 control 或 ablation。

缺哪一项，只阻断依赖它的那个 claim。

## 证据分级与运行

- 每个 run 先声明是诊断还是正式实验。诊断、smoke、mock 和 synthetic 结果都不能支持 claim，也不进最终表格。
- 产出证据的代码 fail fast：同一个 run 里不得自动切换模型、backend、数据、指标或分析方法后继续出结果。修复后用新的 run 重跑。
- 原始 run 不可改写，失败的 run 也要保留。最终表格只从合格的原始记录生成，不手填数字。
- 每个 run 记录能复现它的信息：代码、配置、数据、seed、环境和命令。
- 累计资源触及预算就停；扩大规模要人批准。

## 统计与复现

- 区分描述、探索性比较和确认性推断。确认性分析要在看到结果之前冻结。
- 按真正独立的重复单位（seed、task 或 item）计算不确定性，保留配对结构。不显著不等于等效。
- 同环境重跑只能叫「重放」，不算「复现」。复现外部 baseline 时，自测数字和原论文数字分开列。

## 收尾

原 claim 必须落在 `SUPPORTED`、`FALSIFIED`、`NOT_ESTABLISHED` 或 `BLOCKED` 之一。次要发现单独列出，不能替换原结论。负结果照实记录。
