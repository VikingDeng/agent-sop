# 文档质量规范：引用、图、表、公式、证据

适用于 `/home/viking/dev/docs` 下的 LaTeX / Typst 正式文档工程。
读者是执行检查与修复的 agent，以及负责验收的审阅者。
这份文件是交付检查口径的**唯一详细来源**：项目结构、构建与基线规则见
[../AGENTS.md](../AGENTS.md)，读者逻辑与改写流程见
[skills/research-writing-pipeline/SKILL.md](skills/research-writing-pipeline/SKILL.md)，
日常任务入口见 [agent-tasks/update-docs.md](agent-tasks/update-docs.md)。

字号、间距等排版细节由模板控制；引用样式与编号的语义要求按本文及目标官方规范执行。

## 三类标记

| 标记 | 含义 | 谁下结论 |
|---|---|---|
| `[机]` | 可借现有构建/解析工具逐项核对的稳定不变量 | 执行者按适用工具核对，记录命令与结果；**不表示已经自动化** |
| `[审]` | agent 能且应根据材料完成判断、并在获授权修复时直接改的项 | 执行 agent |
| `[待证]` | 缺证据、取决于作者真实意图或本次无法验证的项 | 作者 / 领域专家 |

- `[机]` 的条目在项目里不一定有现成脚本。没有通用脚本就用适用的构建、解析或检查工具核对，
  人工逐项核对也算，但要记录哪些项没查。扫描范围受模板、宏、动态文件名限制，正则命中不能保证
  资产与引用全覆盖；显式资产清单本身有效（模板名、宏名、生成的文件名扫不到），但清单要能提示
  新增未登记项，只靠清单会漏掉新增图。
- `[审]` 的条目由 agent 判断，在授权范围内修复，不把能判断的语义问题一律丢给用户。
- `[待证]` 只留真正缺证据、或只有作者能回答的要点。
- 每个任务按当前版本重新发现问题，不沿用旧盘点报告里的缺陷计数与警告。

## 一、引用与参考文献 `[机]` `[审]` `[待证]`

### 正文标注形式

- 内部中文文档默认**顺序编码制**，正文文献标注用**上标方括号**：如「相关工作支持这一判断」后紧跟
  上标 `[1]`。默认位置在所支持的短语或句子之后、句末标点之前。
- 目标会议、期刊、学校对引用样式有明确规定时，**官方要求优先**：上标或不带上标、顺序编码制或
  作者-年制、括号形状、`\cite` 的哪个变体，都按官方模板或 CSL 执行。
- 上标是本仓库内部中文文档的默认，不是对所有使用场景的一刀切结论：期刊、学校与出版社各有自己的
  正文标注规定，不要把「本仓库默认上标」写成「所有 GB/T 7714 引用都必须上标」。
- 项目 README 记录本项目实际使用的样式与渲染入口（哪条命令、哪个宏或 CSL 生成正文标注），
  便于复核与交接。

### 编号与重编号

- 默认顺序编码制下，同源重复引用复用同一编号；编号由**首次引用顺序**决定。
  官方要求其他编号或排序方式时从其要求；作者—年份制不套用数字编号规则。
- 组引用（`[1,3,5]`）、条目排序、连续号合并（`[1-3]`）由引用引擎处理，不手工维护。
- 重编号按稳定标识（引用 key、DOI、标题）逐条建立**旧→新映射**，正文、图注/表注、文末文献表
  一起更新。不能依据 `.bib` 文件行序猜编号（行序会变，且 pandoc/CSL 的排序规则与文件顺序不同），
  也不能只比较编号集合是否相等——集合相同仍可能整体错位。

### 不做文献上标转换的对象

- **文末参考文献条目前的 `[1]` 是普通基线字号**，不能变成上标。
- 代码、数组或区间下标（如 `a[1,3]`）、数学指数、脚注、图表与公式编号，都不做文献上标转换。
- 链接样式不能抹掉上标：`\hyperlink`、`#link` 包住引用后仍应是上标；同时避免重复上标——
  引用引擎已经生成上标时不要再包一层。

### 渲染链路

- 用语义引用命令加样式控制真实渲染：Typst 用 `#cite(<key>)` 配 `#bibliography` 与模板样式；
  LaTeX 用 `\cite` / `\citep` 变体配 `.bst` 或 `biblatex` 样式；Pandoc 按实际链路用
  `--citeproc` 加 CSL，或项目里已经验证过的过滤器。
- 不能把所有 `[数字]` 用正则批量替换成上标（会误伤区间、编号与代码）；不能写 Unicode 上标字符
  手工维护引用（`¹` 之类无法重编号、无法检索、复制后失真）。
- 旧项目允许保留已经解析好的文献表，但必须声明**唯一事实源**与可靠的编号映射，为了统一格式
  盲迁移到另一条链路不在允许范围。
- 默认保留项目现有引擎与模板；优先用项目配置或扩展接口实现上标，改完检查全局 show rule 是否
  误伤了图表编号。

### 文献数据

- 文献数据只有一个维护源，新项目优先 `references.bib`；不维护两个互不校验的列表。
- 条目按类型补全：作者、标题、年份、载体，以及适用的卷期、页码、DOI、URL、版本信息。
- **没有 DOI 不得捏造**；网页记录实际访问日期，不从发表日期推算；数据集与软件记实际使用版本，
  作者、版本等未知字段不乱补。
- 全项目采用同一种参考文献样式；内部默认条目编号 `[n]` 在基线、续行悬挂缩进。
  标题中的专名与缩写保留正确拼写，不为统一大小写损坏含义；官方模板优先。

### 检查什么

- 正文每个引用 key 在文献源里存在，没有悬空引用，也没有该引未引。
- 重复条目、同源不同版本（预印本与正式版、会议版与期刊版、数据集版本）。
- 核对全部引用的 key / 编号与文献身份映射；解析可查完整映射，视觉抽查不能替代映射核对。
  特别复查重编号、同名条目与不同版本，避免引用整体错位。
- 未引用条目：必要的延伸阅读可以单列保留，不一律删。
- 格式一致（作者名、标题大小写、期刊缩写、标点）与长链接溢出。
- **数目相等不是映射正确**：正文引用数与文献表条目数相同，也可能整体错位。

### 证据支持关系 `[审]` `[待证]`

- 来源真实与「支持该句」分开核查；DOI 能解析不等于看过正文。
- 关键结论、精确数值、直接引语、可疑引用要回查可访问的原文、表、章节或页码，
  按实际访问范围报告（只看到摘要就按摘要写，不写成读过全文）。
- 引用精确支持对应版本与条件，预印本不冒充正式发表。
- 资料缺失只报告影响结论的缺口，不擅改学术含义、不编条目或补未经核验的引用。
  已查实且支持原主张的引文纠正或补充，在授权修复范围内直接完成并记录依据。
- 可以用已授权可用的只读检索核对来源；不可访问就如实记录，不推测内容。

### PDF 抽查 `[审]`

- 在最终 PDF 里抽查：单引用、同源重复引用、组引用与连续范围、图注与表注里的引用、
  文末条目、链接样式。文档里没出现的形式标「不适用」，不写成通过。
- **PDF 文本提取不能证明上标位置**，提取结果里上标与普通文本常常无法区分；上标判定看渲染后的
  视觉，或用能返回基线/字号信息的提取方式。

## 二、图的交付物与图源 `[机]` `[审]`

- 正式文档里的流程图、架构图、时序图、数据流图、框图，**交付物是图片**：Typst 用
  `#figure(image(...))`，LaTeX 用 `figure` 环境加 `\includegraphics`。
- **Mermaid fenced block、ASCII 箭头、纯文字列表是草稿，不是正式图**，正文里不摊开它们充数；
  「正文里有一段 Mermaid 代码」不算有图。Mermaid、TikZ、draw.io、Graphviz 只是可编辑源或生成工具。
- 可编辑源放工程 `assets/` 下；可重建的导出物优先放 `build/figures/`，由构建命令生成。
  已经导出到 `assets/figures/` 交付的旧项目可以继续，但要在项目 README 说明来源与重建方法。
  记录实际使用的生成命令与工具版本；手工导出的图记录工具及导出设置，保证后续可重导。
- 交付格式按目标引擎**实测**能引入的格式选，不笼统承诺任意引擎都原生支持 PDF/SVG；
  矢量优先，PNG 只用于确实需要位图的情况（截图、位图工具输出），分辨率按最终版面尺寸折算
  不低于 300 dpi，含细线、箭头或小字的图建议 600 dpi。
- SVG 自身既是源又是成品时不必复制两份；手绘源（draw.io、手绘扫描等）只要能导出就不阻塞，
  不为图新增全局工具绑定或渲染依赖。
- 不用截图作为唯一图源。截图不能改字、换字体、重导分辨率；只有外部材料确实拿不到源时才接受，
  并在项目 README 记录来源与不可编辑的原因。
- 构建用导出物，改图改源；源与导出物版本不一致时以源为准重新导出。

```text
assets/figures/pipeline.drawio    可编辑源，改图改这里
build/figures/pipeline.pdf        导出物，由 #figure / figure 引入正文
```

交付前逐图核对：

1. 正文引用的图文件存在，且就是该图题的导出物——结合实际 include、模板、宏、生成依赖与
   显式资产清单核对；扫描 Typst `image(...)`、LaTeX `\includegraphics` 与 Markdown 图片语法只是入口，
   不能只查固定清单或把正则当完整解析，新引用也要覆盖；
2. 导出物能追溯到可编辑源；SVG 源与成品合一、外部材料无源等情况按前述例外记录；
3. 导出物能打开，不是 0 字节或占位空文件；
4. 图题在图下方，编号与正文引用齐全（同第四节）；
5. 最终 PDF 里的图可读（线条、字号、箭头、灰度或黑白打印，见第十节）。

正文所需图片缺失时，交付检查必须失败。草稿可按项目已有机制明确示缺；
不要求构建吞掉缺图错误，也不为方便改文字削弱现有构建检查。

## 三、不同图种看什么 `[审]`

图题说明这张图回答什么即可，不必写成疑问句。各类图的判断点不同，不给所有图硬套同一套标准。

**流程图**：节点是动作、判断或输入输出，不是名词堆；有方向的边写清通过条件，无条件的边不必
凑条件；二元判断的两支都不为空，非二元的判定不必强分两支；按需要画异常或边界路径，
不凭空编异常；输入、输出端点各至少一个；图例只解释读者会误读的记号。
发现含混时指出具体节点、连线或去向，依据正文与材料修正；没有依据的分支留待证，
不因缺少不适用的异常路径就删图，也不凭空补重试或回退。

**架构图**：看组件、职责边界与依赖方向，组件用名词是正常的，不套流程图的边条件要求。

**时序图**：看参与者、消息顺序与时间方向是否清楚。

**数据流图**：看数据对象、加工环节与传递方向是否闭合。

**数据与实验图**：保留数据来源、处理与绘图脚本或可复现步骤；核对坐标轴、单位、尺度及截断、
样本量或预算、误差条与统计量的定义，不编造数据点、曲线或置信区间。
同一颜色在各图保持相同含义，并用线型或形状辅助区分，保证灰度下仍能读懂。

图题、编号、正文引用齐全只说明图能被引用，不说明图站得住；图画对了也不能用源码代替图片交付。

## 四、编号、引用与图表版式 `[机]` `[审]`

- `[机]` 正式编号的图、表、公式都要有稳定 label，正文至少引用一次。Typst 用
  `#figure(...) <fig:name>` 加 `@fig:name`，公式用 `<eq:name>` 加 `@eq:name`；
  LaTeX 用 `\label{fig:name}` 加 `\ref{fig:name}`。
- `[机]` label 不冲突，引用无悬空；图、表、公式按各自计数器与章节/附录规则正确编号，
  不要求全篇扁平连续。自动或手写编号都检查最终结果，编译通过不能替代核对。
- 图与表按**语义种类**区分：图用图号、表用表号。Typst 的 `#figure` 可根据内容推断 `kind`，
  内含 `table` 不保证得到图号；必要时显式设定种类并验证计数器与引用。流程图等仍须按第二节
  以图片交付，不能用表格布局代替最终图片。
- 引用要有目的：指向读者此刻要看的对象。通篇「如下图所示」式的填充引用报出来；
  无引用的图表先判断叙述或附录用途：需要时补有信息的引导，确实冗余才删，避免凑引用。
- 格式遵从模板要求，内部默认表题在上、图题在下。

## 五、表格 `[审]`

- 表用于并列比较与查找；正文一句话能说清的判断不要拆成表。
- 列定义、单位、样本量或预算、分母、时间范围、指标方向（越大越好还是越小越好）写在表内或
  表注里；正文引用的数字与表里的口径一致。
- 有效位数统一到该列需要的精度，不靠多写小数位制造精度。
- **缺测与 0 不同**：没有数据、未测到、不适用分别标注，不写成 0。
- 跨页的表重复表头；表过宽时调整列宽、字号或拆表，不裁掉列。
- 占位与示例数据标「（示例）」或「占位」；引用文献数据的列或表注带语义引文，按第一节渲染；
  非文献来源的数据说明出处与口径。
- 增删列在报告里说明理由：删列会改变表的可比性，读者看不出来。

## 六、公式与符号 `[机]` `[审]` `[待证]`

- `[机]` 抽取公式里的符号，与符号表对账，列出没有定义的符号作为候选提示。
- 符号首次出现的上下文里就地定义，量纲与单位前后一致，标量与向量、索引的取值范围写清。
- 公式写清作用与成立条件；需要后续交叉引用的公式使用当前引擎支持的编号与 label，
  验证最终编号及引用；不凭数学定界符推断整个工具链是否支持编号。
- 编号只需满足引用需要，章节号或附录号本来就不要求全篇扁平连续。
- 符号解析只能给出候选：是否真的没定义、量纲对不对、推理是否成立，由 agent 按上下文核查，
  只有关键材料缺失才让作者判断。
- 不为每个局部变量强行建符号表：只出现一次、紧跟定义的量不必单独列条目。

## 七、证据与论断强度 `[审]` `[待证]`

- 主张、证据、限制三者可辨：读者能找到该主张依据的图、表、公式或引用，也能找到适用条件。
- 观察、推断、建议不能混成已验证结论。区分「测量到 X」「由此推测 Y」「建议做 Z」三种强度。
- 引用要支持相邻主张，不作装饰；不支持时按第一节核查并修复可查明的错配，
  无法核实时报告，不篡改文献内容去迁就句子。
- 关键结论缺证据时标「未决」，不擅自补理由；结构或逻辑修订中可删除非必要且无依据的评价，
  按写作技能说明实质变化，不为已删除的冗余主张保留补证任务。
- 量纲、统计口径、指标适用性与论断强度先由 agent 根据原始材料和可核查知识判断、修复。
  只有关键证据缺失或取决于作者真实意图时列 `[待证]`，不把整个技术判断交还作者。

## 八、读者、章节与语言 `[审]`

- **是否必需先判断**：本节各项按读者任务、文种与交付要求判断；文种不需要的记「不适用」，
  必需而缺失的按待修/待证报出，不得把缺失记成「不适用」。
- 读者目标清楚；章节层次与跨节衔接自然；术语与缩写在首次出现处说明，同一对象前后用同一个词。
  参考手册为便于独立检索，允许条目内重复必要定义，以保留独立理解所需的信息为度，并保持一致；
  这类局部重复不算术语不一致。
- **结构按文种审查**：调研综述、工程技术文档、研究论文的组织主线不同，先定文种再按对应写法查全篇
  结构（入口
  [skills/research-writing-pipeline/references/document-genres.md](skills/research-writing-pipeline/references/document-genres.md)），
  不拿一种骨架套另一种；章节关系可以是因果递进、并列比较、操作先后或检索并列，不要求每节给下一节
  留结论。全面任务查所选文种的全篇结构，局部任务读相邻上下文及相关图表。
- 摘要与结论只收拢正文已有的判断，出现正文里没有的新结论就是问题；是否检查按文种与交付要求判断，
  要求有而缺失的按待修/待证报出；参考手册、任务指南、短 ADR 等确实无需时不强补。
- 语言按**判断 → 信息 → 措辞**验收：先看技术判断是否成立、是否当前解释所必需，再看支持它的
  信息、依据与句间关系，最后才看措辞；诊断出的问题要在改稿里真的解决，不能只调整密度，也不把
  语义判断交还作者。
- 细则见 [skills/research-writing-pipeline/SKILL.md](skills/research-writing-pipeline/SKILL.md)，
  语义验收与回归见 [agent-tasks/update-docs.md](agent-tasks/update-docs.md)。

## 九、代码、伪代码与算法 `[审]`

- 代码、伪代码、算法要能读：输入、输出与正文描述一致，变量名与公式里的符号对得上。
- 没有实际运行的命令示例不算验证，不写成「已验证」。
- 润色不让数值与对象的绑定、论断强度发生漂移。

## 十、最终 PDF 检查 `[审]`

- **页面问题必须看 PDF，不能用源码 grep 当视觉验收**：源码里位置正常，不代表渲染后不溢出。
- 逐项看：封面与目录、页码、字体缺字、上下标、孤立标题、表格跨页、裁切、图分辨率、
  链接、参考文献。这一轮验证的是**当前产物对应的源版本**，产物与源不一致就重新构建。
- 机器能定位的问题（缺字、页码、链接目标）用工具列位置；图与版面的观感由 agent 目视。
- 查看最终 PDF 的渲染页面，记录检查范围；没有视觉检查能力或未打开的页面如实记未检查，
  不能用构建成功冒充全篇视觉验收。

## 十一、交付残留 `[机]` `[审]`

- 清理正式交付里的 TODO、占位符、缺图、生成器旁白、跨机器的绝对路径。
- 保留必要的「未决」与局限说明，不为了干净而删掉作者写下的限制。
- 产物对应最终源版本。

## 不要规范化

- 不引入 AI 检测分数、禁词表、「每段必须一个问题」。
- 不规定图的数量或图文比例，不强制某一种制图工具。
- 不把 Mermaid 与 ASCII 箭头当正式图，也不因此禁止用它们做草稿。
- 图片规范只管交付形式，不能替代图的内容审阅（见第三节）。
- 不管「图 N.M」的空格、字号这类排版细节，那是模板的事。
- 不把 `[审]` 与 `[待证]` 的条目做成脚本判分：脚本只能提示位置，
  判定合格需要读者与领域知识。
