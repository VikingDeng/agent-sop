## 二、固定决策（v1.0）

以下七条是 v1.0 已定决策，执行时按此默认，不再逐次讨论。

1. **文种只有三类**：调研综述、工程技术文档、研究论文。按读者任务选主文种，混合内容按当前段落职责处理；标题里的「报告」「论文」「技术文档」不足以定文种。用户明确指定时以用户为准。入口：`references/document-genres.md`。
2. **引用默认上标，官方要求优先**：内部中文文档正文默认顺序编码制上标方括号（`[1]`），位置在所支持短语或句子之后、句末标点之前；文末参考文献条目前的 `[1]` 保持常规基线字号。目标会议、期刊、学校有官方规定时，样式、编号制、括号形状与宏/CSL 一律按官方执行。由语义 citation + bibliography 或经验证的项目过滤器渲染，不做 `[数字]` 正则批量替换。细则：`document-quality.md` 第一节。
3. **正式图在正文里是导出的图片**：流程图、架构图、时序图、数据流图由 `#figure` / `figure` 引入图片，Mermaid fenced block、ASCII 箭头、纯文字列表都不算图，正文不摊开 Mermaid 源码。可编辑源放 `assets/`，可重建的导出物优先 `build/figures/`，保留可编辑源，交付前逐图核对。细则：`document-quality.md` 第二、三节。
4. **正文改写按「判断 → 信息 → 措辞」**：先核对材料支持什么判断、读者此处需要什么判断，再组织信息与依据，句式最后处理；不能先定结论再挑支持它的材料。合理的对照要保留，反驳句式不是默认连接器，事实、数值、引用与论断强度受保护。判断标准：`SKILL.md`；真实对照：`references/reader-examples.md`。
5. **最终必须构建并看 PDF**：`make build` 通过不等于交付合格；页面问题必须看渲染后的 PDF（封面与目录、页码、缺字、上下标、孤立标题、表格跨页、裁切、图分辨率、链接、参考文献），并记录检查范围与未检查项，不能用构建成功冒充视觉验收。细则：`document-quality.md` 第十节。
6. **工程源与产物分离**：内部报告默认 Typst，官方会议、期刊或学校要求优先；正文按章节分文件，`main.*` 只组装，模板固化到 `vendor/template/` 并由 `template.lock` 校验，产物进入 `build/`，基线只读放在 `_baseline/`。目录和构建硬规则以 `AGENTS.md` 为准。
7. **改稿有固定先后**：先定读者、文种和全文判断，再检查章节关系与证据，再改段落和句式，最后构建并做 PDF 验收。语言顺滑不能替代结构、证据或版式检查；缺证据的结论保持「未决」。

## 三、允许的变更

冻结不等于不修。以下三类允许直接改，改完在第五节「变更记录」追加一行。

| 类型 | 范围 | 要求 |
|---|---|---|
| 事实、链接与兼容性修复 | 错误事实、失效路径或链接、兼容符号链接下打不开的相对路径 | 附核对命令或结果；只修错误本身，不顺手改写方法正文 |
| 官方模板升级 | 会议、期刊、学校发布新官方模板或新引用样式要求 | 按 `AGENTS.md` 第 4 条保存旧基线并逐页比对；`template.lock` 显式更新，不用重建冒充旧基线 |
| 由真实失败案例支持的新规则 | 实际交付中暴露的问题，有可复核证据，足以支撑一条新判断或新检查项 | 写清案例、证据与适用边界；先落到对应源文件，再在本文件登记，不为假想问题加规则 |

不允许的改动方式：为消除报错削弱检查、改写 `template.lock` 或重编旧基线；用未经案例支持的个人偏好替换已有决策；把单个项目的局部约定写回 `_shared` 通用源。

## 四、明确不引入

- **不引入 AI 检测分数**或「去 AI 味」评分（含句式统计打分）。自动计数只是线索，不能证明语义不变，也不是验收证据。
- **不引入禁词表**或按词频判分。「方向」「机制」「意义」等词只有在断言无法定位时才是问题，按语义判断，不按词表。
- **不新增文种分类**。三类之外的内容按当前段落职责并入最接近的一类，不另立第四类框架，也不新增平行的写作框架文件。
- 不把 `[审]` / `[待证]` 条目做成脚本判分或合格线；判定合格需要读者与领域知识。与 `document-quality.md`「不要规范化」一节一致。

## 六、日常调用

一句自然语言即可，不必写长 prompt：

```text
按 docs 规范把 <项目> 全面检查并修复，引用统一上标，完成后给 PDF 和未决清单。
```

「全面检查并修复」默认覆盖 `document-quality.md` 的全部检查面；只审阅时明确说「不要改文件」。执行口径、可改范围与报告要求见 `agent-tasks/update-docs.md`。
