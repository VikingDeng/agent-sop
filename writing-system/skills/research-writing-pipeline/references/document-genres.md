# 文种：按读者的任务选三类写法

本文件只回答「这份文档要怎么组织」。共用要求（判断 → 信息 → 措辞、真实性、有据可查、信息增量、
正向表达、不造误解）与读者、事实保护条款在 [../SKILL.md](../SKILL.md)，引用、图表、公式、证据与
交付检查见 [../../../document-quality.md](../../../document-quality.md)，这里不重抄。

| 三类 | 读者要完成什么 | 默认起稿模板 |
|---|---|---|
| 调研综述 | 掌握现状与差异；用于选型时按约束给建议 | `chinese-research` |
| 工程技术文档 | 理解机制，或评审/实施一个方案 | `modern-technical` |
| 研究论文 | 复核一个新贡献及其证据 | 未定投稿用 `generic`；已定目标用对应官方模板 |

选哪一类看读者拿到文稿要完成什么，不看原稿既有的章节结构。能从头注、源稿与上下文推断就直接做，
不问用户选菜单或填表；只有用途无法推断、且会明显改变主张时，才问一个必要的问题。
一份文档里出现别类的段落，按当前段落的职责处理，不再分新类。

## 调研综述

**主要问题**：材料覆盖到什么程度、各工作的比较口径是否一致、差异来自哪里、共识与分歧卡在哪个
条件、缺的是哪类证据；选型任务还要回答在当前约束下选哪个、代价是什么。事实、被引作者的主张、
综述者的综合与建议要分清。

**可选骨架**：范围与材料（对象、时间、来源及覆盖范围）→ 比较维度
与口径 → 异同解释 → 共识、分歧与缺口 → 选型时按约束与成本收益收敛建议。骨架可以删改。

**连接与证据**：按比较口径连接工作，防止逐个罗列后没有综合；时间先后不证明承接或进步。叙述综述
不虚构系统检索流程；只读到摘要就按摘要的粒度写，不凭未读到推断原文没有，并把由此留下的缺口写明。

## 工程技术文档

**主要问题**：读者是要理解一套机制，还是要评审并实施一个方案。前者要能解释、能预测、换条件能
推断；后者要能复核约束与取舍、照着落地。按用途选侧重，两者是同一类的两种写法。

**可选骨架**：解释侧重用疑问/现象 → 必需概念 → 中间机制 → 可复算示例 → 边界与失效；设计侧重用
约束与问题 → 备选与被否理由 → 决策与代价 → 设计与接口 → 失败处理与验收。按实际用途取所需部分。

**连接与证据**：解释类按认知依赖推进，示例要与刚讲的机制相扣；设计类的连接是约束 → 选择 →
影响与权衡。并列模块允许平行介绍，各节可以独立阅读。分清现状、
已批准、拟议与未知；没实测的输出不写成「已验证」。

## 研究论文

**主要问题**：一个新贡献是否成立、在什么范围内成立，哪条证据支持它，换个数据集、规模或假设还
成立吗。贡献类型允许交叉，按实际主张写清各自需要什么证据。

**可选骨架**：摘要、引言、主体、结论按文种与投稿要求取用，要求有而缺失的指出来，不硬凑固定节
数。主体按贡献给证据：方法贡献给问题设定、机制构造与匹配对照；系统贡献给约束、设计与测量；理论
贡献给假设、定义、命题、证明与边界反例；实证贡献给研究问题、数据与采样、测量分析与效度讨论。

**连接与证据**：按实际依赖组织，问题分解、构造解释、并列证据、结果解释都合法，并列贡献允许平行
铺开。方法设计与评估协议属于论文证据链的一部分，出现在论文里不改变文种；无实验的理论证明按贡献
验收，不强加基准实验。

## 共用边界

- 三类全篇组织可以不同，共用判断不重复；骨架可删改，不强制每段留问题、不要求每章前后线性递进，
  并列对比合法。
- 依据与主张相称：缺证明、缺对照、缺复现或条件不足时写明缺哪一类，标「未决」，不用措辞补成结论。
- 观察、推断与建议分开写；不把「没有读到」写成「不存在」，也不把建议写成已定案。

## 交付与投稿目标

顶会论文是研究论文的具体投稿目标：会议、年份与 track 的模板、贡献与证据要求在实际写论文时按
官方要求核对，不单独增加文种。需要模板时按
[../../../paper-templates/TEMPLATE_CATALOG.md](../../../paper-templates/TEMPLATE_CATALOG.md)
选对应模板与正文骨架。目标样式可以覆盖内部呈现惯例，真实性、论断边界与证据强度不能被覆盖。
