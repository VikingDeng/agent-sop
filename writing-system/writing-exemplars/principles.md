# 七条可执行原则

从 A2、B1、B3、C1、C2、D1、D3 归纳——本库 `status=verified` 的条目，含义是**所选片段与组织做法已核对、可作局部正例**，不是整篇质量背书。每条绑一个正面例和一个判断问题，例子的详细结构在 [macro](macro-structure.md) / [micro](micro-structure.md)；改稿流程按写作技能执行，本文件管**在某一段上具体问什么**。

**信息密度指一段文字相对其长度，让读者多掌握了多少可用于判断的东西**，不是术语数量或字数。机制中间环节、关键比较与口径、适用条件、可验证推论都算增量；依据是读者缺哪一项，不要求每段凑齐数字和结论。

## 1. 先定读者读后能做什么

**增加的理解：目标。** 写明读者读完要能解释、区分、预测或判断什么，再决定写哪些信息。

**正面例：C1。** §15.1 开头声明本节让读者能自己作精确分析，并给前置限定 `Basic familiarity with binary floating-point representation is assumed.`——读者知道需要什么基础、读到哪算读懂。

**判断问题：** 这段要让读者多会做什么？答不出就是没有目标；不以字数、术语数量或段落长度打分。

## 2. 增量取当前理解缺的那一种

**增加的理解：依据。** 机制中间环节、证据与口径、边界与代价是增量的不同形式，只补读者此刻缺的那种。

**正面例：C2。** 「与 ANSI 可重复读隔离级别的区别」先让步承认名称相同，再指名外部判据，把「TiDB 属于哪个隔离级别」从厂商自称变成可查的分类，最后落到具体异常名；该节没有重复介绍隔离级别是什么。

**判断问题：** 读者此刻缺的是机制、口径、条件还是代价？补不出的那一项才是这次要查要问的。

## 3. 一两个有区分力的例子胜过一串名称

**增加的理解：分辨力。** 例子要承担对照功能，让读者自己推出结论。

**正面例：C1。** 从十进制 1/3 写成 0.3、0.33、0.333 引出「停在有限位只是近似」，再换到二进制 0.1 的无限循环，读者由此自己得出 `0.1 + 0.1 + 0.1 == 0.3` 为假，也知道 `==` 在这里为什么不能用、该换成什么。

**判断问题：** 删掉名称清单后，读者还能不能从例子里分辨差别？不能就换例子，不是加名字。

## 4. 缺证据不能靠句式补

**增加的理解：范围。** 材料不足时把缺口的位置与范围写清，不用排比、「全面梳理」这类措辞盖过去。

**正面例：A2。** 清单前先给纳入规则、再给截止时点（「本节只收录开源的测试工具」「表 9 中的链接收集于 2024 年 9 月」），读者据此知道清单是抽样不是穷举。有效的范围陈述可以直说，不必每处都拉对照对象。

**判断问题：** 这句的深度来自新查的资料、分析或实验，还是只来自句式？只是句式就补查并注明范围，或标「未决」。

## 5. 组织降低回读与记忆负担

**增加的理解：连贯。** 先行概念、稳定指代、对照维度、必要的复述要保留，读者不该为理解当前段往回翻。

**正面例：B3。** Summary 交代做什么并指明剩余限制在哪一节；被否方案反复用同一个检验例（Problem Case #3）当「能否接受」的判据，读者不必每节重建比较口径。

**判断问题：** 本段依赖的概念、指代、对照维度前面出现过吗？没有就先给；已定义清楚的不必每段重讲。

## 6. 顺序由读者需要决定

**增加的理解：可达。** 结论可先给后展开，也可先演示再概括；不把「背景 → 机制 → 结果」硬套到每段。

**正面例：B1。** Summary 先给做什么与当前状态，Motivation 再给理由与 Goals / Non-Goals，读者带着「这次做到哪」读机制与测试方案；C1 的导言顺序相反——先现象、类比与反例，最后才归结因。

**判断问题：** 读者此刻更需要先知道结论，还是先看见现象？按这个答案排，不按模板排。

## 7. 强度与状态分开写

**增加的理解：可依赖程度。** 措辞强度决定读者能据此做多重的动作；状态词决定读者会不会把「计划」当成「已完成」。

**正面例：D3。** §3 把 SHOULD 的偏离写成三步：允许偏离的条件 → 偏离方必须完成的判断义务 → 时序；§4 在同一位置换弱情态词，强度差是句法可见的。B1 用 `Currently (v1.35)` 把当前实现与长期承诺分开；D1 的修复清单用 `(Done)` / `(Inspection complete)` / `(ETA: …)` 标出一部分条目——**没标状态的条目只是页面上没标，不等于未完成。**

**判断问题：** 这条结论的强度落在哪一档？改强度词与版本限定词时，有没有把计划写成已完成？

## 按文种取用

上面是判断问题，不是齐备性清单：**性能比较**要对齐口径、指标名、样本与周期；**操作手册**要步骤可执行、有回滚点与验证判据；**执行计划**要给责任主体与完成判据；**技术解释**写实机制与条件即可。形式定义、数学论证、描述性事实各有证据方式，不必都套成「测量 / 推断 / 建议」。

## 理解迁移检验

对**关键段落抽样**（不是每段测验）：设想一个相关但不同的条件，问读者能否据此预测结果、区分两个相似做法或判断该选哪个，并说出**依据**与**仍未知处**。

## 教学假设微例（假设，非实测）

四个逐项等待的 I/O 请求各需 50 ms。在服务端可并行、无共享瓶颈、调度开销忽略的假设下，依次发出后总等待接近 50 ms 而非 200 ms；并发减少的是**等待的重叠**，不减少单次请求的服务时间。据此可预测：一旦服务端串行处理，或四个请求共享同一把锁，总等待就回到相加量级，这时不能再用「并发提速」解释结果。该例是假设推演，不是实测。

## 不产生验收标准

本库只给检查动作在某篇来源里成立的条件与反例；文档是否合格按 `_shared/document-quality.md` 判定。
