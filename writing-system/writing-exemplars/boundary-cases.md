## A1 Holistic Evaluation of Language Models

**可学的局部**：§8.1 把被排除的口径（efficiency）连同理由写在结论旁边；推断句把限定条件嵌在同一句里（参数量差 10 倍以上、共同点是 instruction-tuning），强度压在 `this suggests`；不符趋势的观测保留并给竞争解释；§11 把限制分成 results / implementation / design 三类并落到数字（3 个随机种子、1000 个实例、只做 5-shot prompting）。

## A3 大模型关键技术攻关与产业化发展的启示与建议

（期刊论文，《中国科学院院刊》2026, 41(8): 1683-1692。）

**可学的局部**：§3 的问题清单与 §4 的建议清单共用同一分组与顺序，建议段开头用显式回指「为应对上述挑战」声明对应关系；量化断言带齐对象 + 数值 + 单位 + 年份；现状段用「已取得进展 → 然而 + 短板枚举」的让步—转折骨架，转折后落到具体对象；建议句写成「动作 + 对象 + 手段」。

**原文本身的缺陷**：量化证据多来自付费商业报告，只标机构、不标页码或表号，作「量化 + 标注来源」的范例合格，作「证据可回溯」的范例不合格；建议普遍缺代价、责任主体与适用条件；正文没有独立的限制与不确定性段落；数据句之后紧跟评价句而评价句未给依据。出版机制（双语图题、顺序编码制参考文献）由期刊排版系统提供，Typst / pandoc 工程要自己实现；页面另有一处时间不一致（脚注⑩、⑬晚于所标修改稿收到日期），那是页面本身的，记录如实指出。**一处更正**：观察/判断/建议的措辞例子（「根据我们的调研」「我们认为」）出自 **A2**，不在 A3。

## B2 美团搜索 3.0：LLM 语义表征在排序模型的探索与应用

**可学的局部**：§4.2 先给同场景对照数字、再解释机制，末句用同一组指标回扣首句；被否方案写「能做到什么 + 受什么限制」（底层拼接让语义特征参与特征交叉，但分桶离散化后信号被压缩；输出塔前注入保留连续相似度信号，但无法与其它特征交互），两个分句共享同一评价维度；承认负向结果（「+8bp，且部分指标负向」）；跨场景复用先给覆盖率数字。

**能学一半，加两处本次读取缺口**：四个方案里只有第四个写了指标名，前三项只给 +7bp / +18bp / +8bp，未在同一句点明指标名、样本集、流量比例与实验周期——拿它当「同口径比较」的范例，会把只写 bp 值的写法当成合格；取舍与验证证据来自公司内部能力（近两个月 3000 余万条样本、20%/10% 流量 A/B），不能照搬或编造同类数字。读到的页面里没有描述回滚、灰度切流与压测，限制也散在各节、没有独立的约束/非目标节——这些只说明**页面上没写**；对博客体例来说限制分散是可接受的组织方式，是否独立成节取决于读者任务。8 张图只读到图注。

## D2 关于语雀 23 日故障的公告

**为什么进边界区，以及它可学的局部**：官方原文需要微信内置浏览器 UA（MicroMessenger/8.0.42）并跟随跳转才能取到，普通 UA 被 302 到验证码页而 HTTP 状态码仍是 200——只看状态码会误判为链接正常；本次完整读到的是第三方镜像的逐字转载，镜像与官方逐字一致只在这一份对照上成立。这是可访问性的记录，**不要求另定访问政策**。可学的局部：把总时长拆成「时刻 + 主体 + 动作」三元组（14:07 收到报警 → 14:15 尝试重新上线 → 15:00 确认机器类别较老、改为从备份恢复 → 15:10 开始恢复 → 19 点完成数据恢复 → 19–21 点校验 → 22 点恢复全部服务），「7 个多小时」因此可被读者复算；结论句把测量口径写进句子（「用户所有数据均未丢失」只覆盖数据完整性，不覆盖服务可用性）。

**原文本身的缺陷，以及文种差异**：改进措施 4 条里只有第 1 条带完成状态，其余只有「加强」「缩小」「增加」「改进」类方向性动词，没有负责人、完成时间与验收标准，「杜绝此类运维 bug 再次发生」是绝对化的不可验收承诺；因果链最上游只有「新的运维升级工具 bug」一个名字，失效方式、为何绕过原有测试、为何能触及华东生产环境的存储服务器都没有交代，这一环应标「未决」，下游写得再细也补不上。赔偿方案、领会员步骤、致歉语与结尾拔高句属对外公告结构；小标题是加粗行文而非层级编号，也没有参考文献与图表——这些是该文种与平台体例的形态，不能当正式技术文档的模板，也不能反过来记成「缺少什么」。
