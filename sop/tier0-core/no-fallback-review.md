# SOP-no-fallback-review: 零 fallback 审查

- **层级**: tier0-core
- **落实纪律**: P3
- **绑定骨架**: 无
- **通用性档位**: U0(普适,不含技术栈假设)
- **版本**: v1

## 触发条件

每次提交/合并/交付前;任何 SOP 的"失败处理"字段成文时(本 SOP 也用于审查其它 SOP)。

## 前置条件

有一份待审对象:代码 diff、或一条 SOP 的失败处理描述、或一段流程定义。

## 依赖 SOP

无(本 SOP 是被依赖方,被 commit-and-pr、drift-check 依赖)。

## 步骤

1. 扫描待审对象里所有"出错 / 资源不足 / case 不支持"的分支点。
2. 对每个分支点回答一个问题:**"这条路径在异常时,是报错中止,还是继续产出了一个结果?"**
3. 命中下列任一模式即判为违规,记录位置:
   - 吞异常:`except: pass` / `except: return default` / `except: continue`
   - 降级产出:`except: <走另一条路并返回>` / `if not available: <fallback>`
   - 能力探测降级:`is_supported()/is_available()` 为假时走慢路径/替代路径
   - 关键配置静默默认:`{config}.get(key, default)` 用于必需项
   - 文档层等价物:SOP 失败处理写了"降级继续 / 用默认值 / 跳过"
4. 唯一豁免核对:仅当违规点是**外部 IO 的 bounded retry**(下载/跨服务调用),且**重试耗尽后 raise**,才放行;否则不放行。
5. 对每个违规点,要求改成"raise + 明确错误信息"或"留空并显式报告",复审直到清零。

## 门禁

> gate 分型(采用前须声明属于哪型):
> - **阻断型 gate(零容忍)**:用于致命项——降级措辞、造假、无回滚部署、逻辑矛盾。命中即阻断,不放行(继承 P3)。本 SOP 本身、PROSE 红线关属此型。
> - **信号型 gate(高容忍)**:用于风格与优化项——用词偏好、句式改进、可改可不改。默认产出对象已达合格线,只列"待议清单"交人裁决,**不自动阻断**。PROSE 风格关属此型。
>
> 反模式:把信号型判据当阻断型执行,会在合格产出上刷违规点、误杀合理表达——即"靠挑刺体现存在感"。声明 gate 类型是采用前的强制动作。

[SCAN] `gate_no_fallback` 正则扫 `except\s*:`、`except[^:]*:\s*(pass|return|continue)`、可疑 `.get(...)`、`is_available()/is_supported()` 后跟 else。
[REVIEW] 必问:"有没有任何路径,在出错/资源不满足时不报错而是继续产出结果?"

## 完成判定

待审对象中违规点计数 = 0(豁免项已逐条核对满足"耗尽后 raise")。可由 gate 扫描输出 + 人工复审二值确认。

## 失败处理

遵守 P3:若发现违规点无法消除(例如上游库强制吞异常),不得放行、不得"标记 TODO 后合入",必须中止本次提交并如实报告阻塞点;本 SOP 自身执行出错(如扫描器崩溃)同样中止报错,绝不"扫描失败即默认通过"。

## 产物

一份审查结论:违规点清单(位置 + 类型 + 处理方式)+ 二值放行/拦截结论。
