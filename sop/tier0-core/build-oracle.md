# SOP-build-oracle: 建立独立验证 oracle

- **层级**: tier0-core
- **落实纪律**: P2(独立 oracle 验证)
- **绑定骨架**: 无(被 run-experiment、package-submission 依赖)
- **通用性档位**: U0(普适,oracle 思想跨研究/竞赛/开发/写作)
- **版本**: v1

## 触发条件

需要判定某个产物"是否正确",且不能用被测对象自证时(实验结果、竞赛 kernel、库函数、报告论断)。

## 前置条件

- 待验证对象有明确的输入空间与期望语义;
- 存在至少一种**独立参照**的可能来源(见步骤 2)。

## 依赖 SOP

无(基础能力,被上层依赖)。

## 步骤

1. 明确"正确"的定义:对这个对象,正确=输出满足什么可观测性质?写成断言级描述。
2. 选独立参照,优先级从高到低:
   a. 已知解析解 / 数学恒等式;
   b. 独立参考实现(不同作者/不同路径,如 `torch` 参照手写 kernel);
   c. 已知答案的历史数据集 / 黄金样本;
   d. 交叉来源(写作场景:第二个独立信源核验同一论断)。
3. 物理隔离:oracle 代码/数据与被测对象分开存放(如 `src/oracle/`),**绝不复用被测对象的实现**。
4. 覆盖边界:oracle 的测试用例必须含空输入、极端 shape、数值稳定性 case——似是而非的错误通常藏在 happy path 之外。
5. 输出二值:oracle 对拍返回 `pass/fail`,fail 即判被测对象不正确,该产物作废/不予采信。

## 门禁

[SCAN] 校验 oracle 与被测实现无代码共享路径(不 import 被测模块的核心逻辑)。
[REVIEW] 必问:"这个 oracle 会不会其实间接用了被测对象?边界 case 覆盖了吗?"

## 完成判定

- 存在独立于被测对象的 oracle;
- 对拍产出二值 pass/fail;
- 边界用例已纳入。
可查:oracle 存在 + 一次对拍运行 + 用例清单。

## 失败处理

遵守 P3:若找不到任何独立参照(无解析解、无参考实现、无黄金样本)→ 如实声明"当前无法独立验证",不得用被测对象自证冒充已验证,也不得"看起来对就通过";若 oracle 自身运行出错 → 报错中止,不得"oracle 挂了就跳过验证直接采信被测结果"。

## 产物

一个独立 oracle(代码/数据/核验流程)+ 一次对拍的 pass/fail 结论 + 边界用例清单。
