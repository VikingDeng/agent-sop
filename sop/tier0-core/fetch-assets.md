# SOP-fetch-assets: 下载资产(数据 / 模型 / 依赖)

- **层级**: tier0-core
- **落实纪律**: P1(先探源立契约,不凭记忆猜)/ P3(失败即报,不假装成功)/ P4(来源与校验留痕)
- **绑定骨架**: 无(被 run-experiment、ops-remote-compute 等依赖)
- **通用性档位**: U1(下载机制通用;源/校验/目标机为项目相关,以 `{参数}` 注入)
- **版本**: v1

## 触发条件

`[显式]` 需要下载数据集 / 模型权重 / 依赖到本地或远程机时。
`[信号自触发]` 全量任务需要外部资产(语料、评测集、骨干权重)时进入本 SOP —— 先探源与校验,不直接开拉。

## 前置条件

- 候选源清单已列出(官方源 + 镜像,如 HF / hf-mirror / modelscope / 原始文件服务);
- 下载目标已定:**大资产(>GB 级)在目标机(服务器)下载,不本地中转**(科研骨架 §4.6);小资产本地;
- 目标盘剩余空间已知。

## 依赖 SOP

→ tier0-core/add-dependency.md(为下载引入 SDK 时先过准入评估,防依赖地狱)。
→ tier0-core/build-oracle.md(下载后小样本验证 = 独立判据,防"看着像就收下")。
→ tier0-core/lock-env.md(依赖下载后锁定;模型版本 pin 见科研骨架 §4.4 registry)。

## 步骤

1. **探源(实测,不靠记忆)**:对每个候选源做可达性实测(`curl -I` / HEAD / 试连)——**网络环境因机器而异**:本地可达 ≠ 服务器可达(HF 直连可能被重置);上一台机的镜像结论不自动适用下一台。选**可达且版本可 pin** 的源;多个可达时优先版本锁 + 校验完备者。
2. **小样本先验(防返工)**:全量下载前,先取小样本(头 N 条记录 / 小分片 / 单文件)验证**格式、结构、内容**符合预期(记录数、字段、编码、无损坏)。格式不符 → 换源或换解析,不拉全量。
3. **测速与决策**:大文件先测实时速率,估算总时长;进程活着但缓存长期不动 = 龟速,换源/换通道。据此决定前台拉取或后台执行;后台任务与后续工作并行。
4. **执行下载**:后台下载输出重定向到日志;网络 IO 允许 bounded retry(**重试耗尽后必须 raise**,继承 P3);下载脚本保持**幂等**(已完成的步骤跳过),会话中断后可续跑。
5. **校验**:下载完成后核对大小 / 行数 / 哈希 / 格式与来源声明一致;不符 → 判失败重下,不静默接受。模型权重额外做离线校验(`HF_HUB_OFFLINE=1` 可用,科研骨架 §4.4)。
6. **留痕(P4)**:来源 URL、版本/revision、时间、校验值、下载目标机写入 registry(数据卡 / `registry.yaml`)与 provenance;**密钥/凭据永不入库**(放 repo 外 chmod 600,代码只从环境变量读)。

## 门禁

[RUNTIME] 校验通过才进 `processed/`;校验失败即重下,不消费未校验资产。
[SCAN] 无 pin 的 `latest` 拉取;密钥字面量入库;为下载硬装 SDK 未过 add-dependency。
[REVIEW] 必问:"小样本验过格式吗?源在**目标机**上实测可达吗?校验值与来源声明一致吗?"

## 完成判定

- 资产落盘(目标机或本地)且通过大小/行数/哈希/格式校验;
- 来源 URL + 版本 + 校验值 + 时间已留痕(二值:provenance/数据卡可查到)。

## 失败处理

遵守 P3:探源全不可达 → 报告换源/换网络,不硬猜 URL 直连;镜像索引格式不对(如 `versions: none`)→ 在目标机直接探测真实可取的 URL,不将就乱装;下载中断 → 报错并续传/重下,不"大概下完了"继续;校验不符 → 判失败,不静默用坏数据;SDK 依赖冲突 → 回 add-dependency 评估或换零依赖方案(requests/curl),不硬装污染环境。

## 产物

资产文件 + 校验记录(大小/行数/哈希/格式)+ provenance(来源/版本/时间/目标机);密钥零入库。
