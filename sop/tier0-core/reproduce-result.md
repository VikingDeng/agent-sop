# SOP-reproduce-result: 复现一个结果

- **层级**: tier0-core
- **落实纪律**: P2(独立复现即验证)+ P4(可追溯到来源与配置)
- **绑定骨架**: 无(被 run-experiment、ops-deploy 依赖)
- **通用性档位**: U1(依赖锁环境机制,不绑具体栈)
- **版本**: v1

## 触发条件

需要确认某个结果(实验指标、构建产物、部署行为、报告数据)可被再次得到、而非一次性偶然时。

## 前置条件

- 目标结果有明确定义与可接受容差 `{TOLERANCE}`(数值结果需给容差,防浮点/随机噪声误判);
- 环境已按 `→ tier0-core/lock-env.md` 锁定;
- 产生该结果的输入、配置、随机种子 `{SEED}`、代码版本 `{GIT_SHA}` 可获取。

## 依赖 SOP

→ tier0-core/lock-env.md(复现的前提是环境可锁)。

## 步骤

1. 采集复现三要素:代码版本 `{GIT_SHA}`(要求 git 干净)、锁定环境、完整输入+配置+`{SEED}`。
2. 在独立/干净环境按三要素重跑,不复用上次的中间产物/缓存(防"缓存命中冒充复现")。
3. 比对新结果与原结果:数值型看是否落在 `{TOLERANCE}` 内;二值/结构型看是否一致。
4. 一致 → 记录为"已复现"并归档复现清单(三要素 + 两次结果 + 差异)。不一致 → 进入失败处理。
5. 随机性结果:多次(≥`{N_SEEDS}`)重跑报分布(均值±方差),而非单点,避免用一次幸运结果冒充稳定结论。

## 门禁

[RUNTIME] 复现跑在干净环境、`git_dirty=false`;结果落在 `{TOLERANCE}` 内。
[REVIEW] 必问:"这次复现有没有用到上次的缓存/中间产物?种子和配置记全了吗?"

## 完成判定

- 独立环境重跑得到与原结果一致(容差内)的结果;
- 复现三要素 + 结果比对已归档(二值)。

## 失败处理

遵守 P3:若复现结果超出 `{TOLERANCE}` → 判为"未复现",如实报告差异与可疑来源(种子/环境/数据泄漏/缓存),不得"差不多就当复现了";若复现三要素缺失(无种子/环境未锁/代码 dirty)→ 中止并报告不可复现,不得用不完整信息强行声称已复现;复现过程本身报错 → 中止,不得跳过。

## 产物

复现清单:三要素(`{GIT_SHA}`+环境锁+输入配置`{SEED}`)+ 原/新结果 + 容差判定 + (随机性)分布。
