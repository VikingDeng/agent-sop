## Evidence-to-policy changes

1. **Competition correctness** — preserve Luna execution, Terra semantic review, one consolidated correction, and one re-review without adding fixed gates, hashes, or signatures; triage findings by impact on frozen acceptance.
2. **Research integrity** — require self-checks to compare budget/report/actual continuation counts; accept frozen-claim evidence while moving nonblocking configurable-runner issues to pre-scale backlog.
3. **Development review scope** — add bounded REVIEW_PROFILE=ordinary|api|security|architecture/data; API correctness may use Sol risk judgment, while full codex-security workflow requires a concrete adversarial trigger.
4. **Git-root hazard** — check git rev-parse --show-toplevel before the first write, stage, or commit in a new project; use an independent git init or worktree when intended.
5. **Suite contention** — allow one full suite at a time; before restart inspect/close only the worker's own prior process/session and do not launch duplicate heavy suites.
6. **Resume routing defect** — telemetry does not bind agent IDs to package/phase/requested role/actual model/open state, but a global resume ban also forces unnecessary respawns. Advisory mode therefore allows `resume_agent` with an auditability warning; strict mode denies it. Correction/re-review uses a matching live agent only when identity evidence exists and otherwise uses a fresh explicit typed spawn; reuse or role/model changes never reset an applicable budget, and evidenced mismatches keep WCU [UNCERTAIN].
7. **Supervisor monitoring tax** — use one bounded long wait per decision point, compact evidence, and fresh top-level execution tasks for heavy projects when the user can start them. This reduces avoidable polling tax but does not remove the app's need for progress updates.

The adaptive/outcome-first architecture remains in force: these are proportional practices, not fixed gate/hash/signature/validator requirements. Unresolved items remain [UNCERTAIN]; nonblocking hardening is backlog, not a silent acceptance change.

## Semantica #859 bounded repair E2E (2026-08-11)

A clean post-issue worktree reproduced the real visualization-order defect at `10 failed, 48 passed`. The requested Luna implementation spawn failed before work with `Selected model is at capacity`; the supervisor transparently substituted Terra rather than blocking the project or claiming Luna execution. Terra's first patch made both normal and reverse file order pass (`58 passed`), but an independent Terra review demonstrated a concrete remaining failure: the fixture deleted pre-existing `semantica.visualization` module state instead of restoring it. One fresh Terra correction added transactional restoration plus pass/exception regressions. Normal and reverse order then both passed `60/60`; one final bounded Terra re-review returned `APPROVE`, with no production-code changes or weakened assertions.

This is positive evidence for outcome-first fallback, useful independent review, and the one-correction/one-re-review convergence rule. It is negative evidence for guaranteed minimum cost: all four completed children actually used Terra/high because Luna was at capacity. Their raw session totals were 3,628,099 Terra tokens, or 36,280,990 WCU. The legacy App supervisor remained Sol/high and accumulated approximately 5,323,741 additional tokens between adjacent root audit checkpoints, or 133,093,525 WCU; that root delta is `[UNCERTAIN/PARTIAL]` because the checkpoint precedes the user turn after an idle interval. The combined audit-cutoff estimate is 169,374,515 WCU. A long pre-existing Sol foreground is therefore not valid evidence of an efficient fresh-task configuration even when its delegated quality loop succeeds.

## ARC 226 D fresh Terra competition E2E (2026-08-11)

Fresh CLI task `019fef3a-cadf-7eb1-843d-044800c55120` started from the ended official AtCoder ARC 226 D page and a frozen local-only contract. It did not read the editorial or other submissions and made no online submission. The final repository committed a C++17 interactive solver, independent Python protocol/state judge, proof, and reproducible evidence. Strict warnings, ASan/UBSan quick cases, an explicit `-1` protocol probe, deterministic schedules, three seeded random `Q=5000` schedules, and ascending/descending all-pushes-first stress passed. The base-9 construction used exactly 89,331 moves in the worst local schedules, below the 100,000 contract; no AtCoder verdict is claimed.

The trace exposed two routing defects before converging. First, the Terra root spawned Luna implementation and Terra review while the core five-queue invariant was still unresolved; all three duplicated architecture search and produced no artifact. Second, the first Sol architect was allowed only a 60-second wait; the root treated timeout as no result and ended, aborting Sol while it was still reasoning. Recovery used a fresh Sol architect with a five-minute bounded wait. It returned the concrete base-9 construction and closed 89,331 bound; a fresh Luna then implemented the solver and judge. A fresh Terra review approved the construction but found that the judge's `readline()` did not enforce its documented deadline. The Terra root replaced it with timed binary-pipe reads, added explicit `-1` and per-response 5,193 checks, reran the full suite, and committed `5636c3e` locally.

Raw logs prove 2,012,971 Terra root tokens, 243,768 initial Terra-review tokens, 1,274,824 final Terra-review tokens, 539,794 aborted Sol tokens, 782,811 successful Sol-architect tokens, 325,394 initial Luna tokens, and 1,888,406 successful Luna tokens. Total usage was 7,067,968 tokens and 70,594,555 WCU: 35,315,630 Terra WCU, 33,065,125 Sol WCU, and 2,213,800 Luna WCU. Quality and final specialization were strong, but cost was inflated by pre-architecture parallelism, the too-short architect wait, and four-turn child history forks. Policy therefore now routes unresolved critical invariants before implementation/review, treats timeout as incomplete rather than negative evidence, sizes waits to the package, and prefers self-contained minimal-history child packets.

The CLI event stream represented `wait_agent` without receiver IDs even though raw JSONL proved successful child spawns. An earlier live interpretation called these “empty waits”; raw-log audit corrected that factual error. Routing claims must use spawn/result records, not UI event shape alone.

## CPG-IC approved-proposal research E2E (2026-08-11)

Fresh CLI task `019fef60-1e71-70b1-9581-8b47fbc4b14e` started from the approved CPG-IC proposal in an isolated worktree. Its frozen scope was a local four-case `planted_smoke` engineering pilot only: no natural-patch claim, human labels, Phase 0 scientific result, RL, scale, remote work, or publication eligibility. The Terra/high root resolved the execution design before dispatching Luna. Luna committed a subprocess-backed pilot and ran exactly one formal four-case execution. It produced 32 actual verifier calls in 0.927 seconds of summed subprocess time with GPU 0, concurrency 1, and `paper_eligible=false`.

The first checker attempt exposed a case-order fingerprint defect; Luna corrected only the checker and reused the same immutable run. The initial Terra review then returned `NO-GO` on four frozen-contract failure paths: untracked execution inputs were excluded from dirty-state detection, the replay digest only re-hashed one execution, terminal wall/CPU overruns could still emit `done`, and the checker did not independently enforce all four path kinds. One fresh Luna correction closed three paths and added 13 passing focused tests, but introduced a 228-line standalone replay facility. The one permitted Terra re-review found that facility could emit a completed replay artifact without first requiring the source run to pass the independent checker. The task stopped at `NO-GO`; no second pilot or replay ran, and the historical evidence was not relabeled. Local commits `944cf18` and `9753905` preserve the code-readiness patch and final decision.

Raw logs prove 1,576,097 Terra root tokens, 788,806 initial Terra-review tokens, 1,282,733 Terra re-review tokens, 2,337,341 initial Luna tokens, and 2,947,060 Luna correction tokens. Total usage was 8,932,037 tokens and 41,760,761 WCU: 36,476,360 Terra WCU, 5,284,401 Luna WCU, and zero Sol WCU. Quality control and truthful stopping worked, but context routing was inefficient: the correction and re-review inherited several long parent turns, so 7,536,128 of 8,835,417 input tokens were cached (85.3%). Cached context therefore dominated cost even without Sol.

This trace adds two policy corrections. First, implementation, review, correction, and re-review are fresh package boundaries and should normally use no inherited conversation turns; repository artifacts plus a compact packet are the authoritative context. Second, a failed immutable run must remain failed. Fix the next execution path with the cheapest integrated check and require fresh evidence only after new authorization; do not build historical compatibility, replay, or validator machinery to rescue an old verdict. The trace is positive evidence that the repair/re-review cap restores liveness, and negative evidence that a mechanically strict execution contract can still induce guardrail code larger than the four-case pilot unless complexity is treated as a first-class finding.

A post-run root audit found another code-readiness defect that the bounded re-review did not report: the corrected runner serializes absolute paths into `case_links.json`, while the checker requires the configuration's relative paths. The focused suite built link fixtures by hand and therefore missed this producer-consumer incompatibility. No third repair was made after the frozen budget. Policy now requires the cheapest positive producer-to-consumer compatibility check whenever a correction changes a schema or artifact contract; negative regression tests alone are insufficient, while such a synthetic code-readiness check still cannot relabel an old run or consume a new formal-pilot claim.
