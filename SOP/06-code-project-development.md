# SOP 06 — 代码与项目开发规范(DRAFT v0)

> 状态:**草案**。内容由用户逐条审定后定稿。每条标注力度:
> **必须** = 违反即不合格;应 = 默认遵守,特殊情况说明;建议 = 推荐但不强制。

## 1. 仓库基础

- [ ] **必须** README:说明项目是什么、怎么跑、关键命令(build/test/run)。
- [ ] **必须** 项目级 `CLAUDE.md`:技术栈、目录结构、本仓库特有约定;没有就由 agent 在首次开发时创建并随代码提交。
- [ ] **必须** `.gitignore` 覆盖:密钥、运行时产物、IDE 文件、依赖目录、构建产物、日志。
- [ ] **必须** 密钥纪律:`.env` 永不入库;只提交 `.env.example`(含占位值)。
- [ ] **应** 公开仓库才放公开内容;私有/未定仓库默认不公开。

## 2. Git 工作流

- [ ] **必须** commit message 格式:`<type>: <简短描述>`,type 取 `feat/fix/docs/chore/refactor/test/perf`。
- [ ] **必须** 一个逻辑变更一个 commit;禁止一个 commit 混入无关改动。
- [ ] **必须** 禁止提交:依赖目录、构建产物、临时文件、日志、密钥、大文件(>50MB)。
- [ ] **应** 小步提交,可回滚优先于一次性大改。
- [ ] **应** 个人项目可直接推 main;涉及共享/发布的项目先过功能分支。

## 3. 代码质量

- [ ] **必须** lint/format 配置随仓库提交(如 ruff/prettier/black),提交前运行通过。
- [ ] **必须** 风格一致:新代码跟随周围代码的命名、注释密度、惯用法,不引入新风格。
- [ ] **必须** 错误处理:不吞异常;错误信息可诊断(含上下文);失败路径有明确返回。
- [ ] **应** 公开函数/接口有注释或类型标注(按语言惯例)。
- [ ] **应** 避免过度工程:改进量除以新增复杂度不佳的抽象不做。

## 4. 测试

- [ ] **必须** 仓库定义测试命令(如 `pytest`/`npm test`);agent 声称完成前必须运行。
- [ ] **必须** 新功能覆盖核心路径;修 bug 先写复现测试再修(无法写测试的说明原因)。
- [ ] **必须** 测试失败时不许声称完成;如实报告失败输出。
- [ ] **应** 测试与代码同库提交,不算运行时产物。

## 5. Agent 协作(本工作站的 agent 特有)

- [ ] **必须** 运行时产物不入库:任务状态文件(`dev/`)、日志、截图、调试输出。
- [ ] **必须** 变更路径不明显时,先声明验证命令,再执行变更。
- [ ] **必须** 实质改动声称 ready 前过 critic + codex-reviewer(任一 <80 不算 ready)。
- [ ] **必须** 禁止擅自:修改密钥/凭据、删除数据、发起外部请求、改动本仓库之外的项目、push 到非本人仓库。
- [ ] **必须** 改代码同步更新受影响的 README/CLAUDE.md/文档。
- [ ] **应** 需要人决策的点显式提出,不静默假设。
- [ ] **应** 不确定性标注 `[UNCERTAIN]`;数据/安全/归因不清时停下报告。

## 6. 安全底线

- [ ] **必须** 密钥/凭据永远不进代码、注释、提交信息、文档。
- [ ] **必须** 依赖锁定文件入库(package-lock / pnpm-lock / uv.lock 等)。
- [ ] **必须** 安全功能优先用经过验证的库(helmet/DOMPurify/defusedxml 等),不自造。
- [ ] **应** 输入校验、最小权限、SSRF/CSRF/XSS 防护在涉及用户输入或网络时默认考虑。

## 7. 项目生命周期

- [ ] **应** 新项目从统一模板初始化(README/CLAUDE.md/.gitignore/lint 齐备)。
- [ ] **应** 停止维护的项目:README 标注状态,远端仓库可归档。

## 8. 例外与豁免

- 任何"必须"条款在特殊情况下可豁免,但必须:在 PR/commit 中显式说明原因,并标注 `[WAIVER: <条款>]`。
